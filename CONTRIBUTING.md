# Contributing

Thank you for helping. Shifa Pharmacy POS is for real pharmacies, so changes need care: a wrong stock or ledger rule costs money.

## Ground rules

These come from `CLAUDE.md` and are not optional:

- **Vanilla JavaScript (ES2020), HTML and CSS only.** jQuery 3.7 is vendored in `vendor/`. No framework, bundler or npm build step.
- **No new libraries** without an issue first.
- **Layers:** pages (`js/pages`) call services (`js/services`), which call the database layer (`js/core/db.js`). Pages never touch IndexedDB.
- **Every write goes through `db.transaction()`.** Synced writes are queued in the same transaction.
- **Money is integer paisa.** Format only at display time (`js/core/money.js`).
- **Stock is never typed in.** It is the sum of movements. Use the services; never edit `onHand` by hand.
- **Every business document posts balanced ledger entries.**
- **Every visible string uses `t('key')`** and has an English and an Urdu entry. Run `node tests/audit-keys.mjs` to check.
- **No inline event handlers** (`onclick=` and the like). The app runs under a Content Security Policy.
- **User text is escaped** with `esc()` before it goes into HTML, or set with `.text()`.
- **Paths are relative.** The app must work under a subpath such as `/repo-name/`.
- **No business data or secrets in the repository.** Demo data is generated by code (`js/services/demo.js`).

## Running it

Serve the folder over http (the service worker needs it):

```bash
node tests/serve.mjs
```

Then open `http://localhost:8787/index.html`. Any static server works too, for example `python -m http.server 8000` from the repository root.

## Checks

Run these before opening a pull request:

```bash
node scripts/audit-shell.mjs
node scripts/audit-budget.mjs
node scripts/audit-contrast.mjs
node tests/audit-keys.mjs
```

What they check:

- `audit-shell`: the service worker's precache list matches the files, and its version matches `js/core/version.js`.
- `audit-budget`: first-load size (300 KB gzipped budget) and the modulepreload block in `index.html`.
- `audit-contrast`: text and control contrast in light and dark themes.
- `audit-keys`: every translation key exists in English and Urdu.

Then open these pages in the browser and check the results they show:

- `tests/services.test.html`: business rules, ledger, stock, reports and backup (339 assertions).
- `tests/migration.html`: upgrade from schema version 1 to the current version (12 checks).
- `tests/sync-sim.html`: two offline devices and a late joiner converge (20 checks).

For a user-facing change, also work through the relevant scenarios in `tests/e2e-checklist.md`.

## Making a change

1. Open an issue for anything bigger than a fix, so the approach can be agreed first.
2. Make the change in small steps. Each commit should leave the app working.
3. If you change the database schema, add a new migration to the end of the list in `js/core/db.js`. Never edit one that has shipped. Bump `APP_VERSION` in `js/core/version.js` and the service worker `VERSION` in `sw.js` together.
4. If you add a file that the app loads, it must be in the precache list in `sw.js`. `node scripts/audit-shell.mjs` tells you if it is missing.
5. Add a line to `CHANGELOG.md` under "Unreleased".
6. Write a short commit message in the imperative, for example "Add undo for held sales".

## Reporting problems

Open an issue with the steps, what you expected, and what happened. Do not attach backup files or any patient or customer data. For a crash, describe the message shown, not the data on screen.
